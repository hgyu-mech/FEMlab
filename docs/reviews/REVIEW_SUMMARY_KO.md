# 박소연 박사학위논문 비판적 검토와 FEMlab 확장

검토 대상: Soyeon Park, *Contributions to ML-Metaheuristics for structural,
material optimizations and energy consistent particle-based simulations*,
고려대학교, 2025년 8월. 검토일: 2026-09-28.

아래 페이지는 본문 인쇄 번호입니다. PDF 페이지는 19를 더하세요.
이 문서는 원문을 고친 복제본이 아니라 출처를 명시한 독립적인 비평입니다.
원본 코드·데이터가 없는 상태에서 재현했다고 주장하지 않습니다.

## 평가

강점은 실제 공학 문제에서 설계, 데이터 생성, 대리모델, 최적화, 실험을
연결했다는 것입니다. 특히 로봇 시편과 페라이트 제작·측정은 단순한 신경망
정확도 표보다 강한 근거입니다. MPM 전달 매개변수를 학습하는 방향도
해석 결과만 예측하는 것과 구별되는 의미 있는 접근입니다.

반면 모든 문제에서 정확하고 보존적이며 빠른 해석기라는 결론까지
뒷받침되지는 않습니다. 다음은 연구자의 역량에 대한 평가가 아니라,
공개된 수식·검증 절차·결과가 지지하는 주장 범위에 대한 검토입니다.

## 가장 중요한 여섯 가지

1. **계산 기간:** p.81은 데이터 생성 187시간, 학습 13시간을 보고합니다.
   합계는 200시간, 약 8일 8시간입니다. 이 부분은 70일·140일이 아닙니다.
   추론은 시간 단계당 2ms 이내지만 전체 해석 시간은 약 30% 증가합니다.
   추론이 빠르다는 것과 전체 해석이 빨라졌다는 것은 다른 주장입니다.
2. **실험 제약 위반:** p.23 Table 3의 최적 시편에서 B* 측정값은
   CASE1 0.281(요구 하한 0.3), CASE3 0.093(요구 하한 0.1)입니다.
   강성비 개선은 인정하되, 제조 오차를 고려한 여유 없는 최적화가
   실험에서 엄격하게 제약을 만족했다고 말하기는 어렵습니다.
3. **테스트 데이터 재사용:** pp.34, 42, 46, 48에서는 테스트 오차로
   반복 개선과 추가 샘플링을 결정합니다. 이 집합은 검증·획득 집합의
   역할을 하므로 마지막에 한 번만 평가하는 독립 시험 집합이 더 필요합니다.
   이것만으로 테스트 행을 학습 배열에 직접 넣었다고 단정하지는 않습니다.
4. **에너지 식:** p.67 Eq.(39)의 변형에너지에 질량이 추가로 곱해져
   있습니다. 통상적인 응력·변형률·체적 단위라면 차원이 맞지 않습니다.
   유한변형 초탄성에서는 재료의 저장에너지 함수도 확인해야 합니다.
   조판 오류일 수 있으므로 실제 코드 오류라고 확정하지 않습니다.
5. **에너지 손실:** 직접 최적화한 예제의 2.5%와 학습 모델을 넣은 검증
   결과를 섞으면 안 됩니다. 후자는 원판 충돌 26.7%, 외팔보 약 60% 손실입니다
   (pp.73, 77-81). 기존 방법보다 개선됐지만 보존 문제가 해결됐다는 뜻은 아닙니다.
6. **전역 제약과 지역 예측:** 최적화 때 운동량 보존을 걸어도 입자별로
   신경망이 독립 예측한 계수가 그 제약을 자동으로 만족하지는 않습니다.
   계수 범위 제한만으로도 부족합니다. 이를 확인하는 반례와 최소변경
   운동량 보정 코드를 새로 작성했습니다. 보정은 에너지를 바꿀 수 있습니다.

## 내가 발전시킨다면

모델을 먼저 키우지 않고, 물리적으로 틀릴 수 있는 출력을 줄이겠습니다.
보존 제약을 만족하는 표현 또는 투영, 짧은 시간 경로의 물리 오차를 포함한
학습, 전체 궤적·형상·입자 수별 데이터 분리, 실패 사례 보존을 먼저 합니다.
작은 MLP와 선형 모델을 이기고 이웃 정보가 필요하다는 근거가 생기면
GNN으로 확장합니다. 설계 최적화에는 제조 불확실성과 최종 물리 재해석을
넣습니다. 이는 아직 검증되지 않은 연구 가설이며 자동 성능 향상 약속이 아닙니다.

2026년에는 MPM 데이터와 미분 가능한 GNN을 역해석에 연결한 사전공개 논문
(arXiv:2602.11621), 비학습 기반 implicit CK-MPM 사전공개 논문
(arXiv:2604.18917)도 확인됩니다. 전자는 활용 방향, 후자는 더 강한 비교 기준을
생각하게 합니다. 해당 연구의 결과를 독립적으로 재현한 것은 아닙니다.

## 이번 개발의 의미

실제 추가한 것은 운동량 투영, 외력 일을 분리한 에너지 잔차, 반례 실험,
MPM 체크포인트·재시작, 손상·설정·코드 변경 검사, 진행 상황 파일,
짧은 GitHub 실행 워크플로, 서버/HPC 실행 도구입니다.
전체 논문 재현이나 학습된 alpha/beta 시간 적분의 완성은 아닙니다.

GitHub Actions 한 작업으로 140일을 계속 돌릴 수는 없습니다. 장기 계산은
허가된 서버/HPC에 두고 중간 저장해 이어서 실행하는 방식이 적절합니다.
가상환경은 패키지를 분리할 뿐 서버를 만들어 주지 않습니다. 코드 업로드,
짧은 원격 검증, 장기 서버 가동, AI의 지속적인 연구 판단은 각각 구분해야 합니다.
