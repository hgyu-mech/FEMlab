# 학습 데이터와 반복 실행의 예산을 정하는 방법

이 문서는 [Kriging과 고충실도 최적설계](surrogate-optimization.ko.md)를 위한 실험 계획이다. 아래의 표본 수와 seed 수는 실행 순서를 정하기 위한 제안이다. 브래킷에서 필요한 최소 표본 수나 모델 성능은 고충실도 해석 데이터로 확인한다.

## 서로 다른 네 가지 횟수

| 횟수 | 세는 대상 | 어떻게 정하나 |
|---|---|---|
| 고충실도 학습 케이스 $N$ | 솔버로 평가한 서로 다른 설계·정해진 하중 조건 | 시범 학습곡선은 10, 20, 40, 80개에서 비교한다. 케이스 수와 독립 형상·하중 그룹 수를 함께 쓴다. |
| 한 신경망 학습의 epoch | 해당 학습 분할 전체를 한 번 순회한 횟수 | 최대 epoch와 조기 종료 기준을 사전에 정하고 검증 점수로 체크포인트를 고른다. |
| 처음부터 다시 학습한 횟수 $S$ | 다른 초기 가중치·데이터 순서 seed로 모델을 독립 적합한 횟수 | 디버깅은 1회, 시범 비교는 3개 고정 seed, 결론이 seed에 민감하면 최종 후보만 사전 정의한 10개 seed까지 확장한다. |
| 데이터 갱신 횟수 | 새 DOE 배치를 실제 해석하고 모델을 갱신한 횟수 | 다음 배치의 방향과 크기는 성능 차이, 제약 경계의 불확실성, 잔여 해석 예산으로 정한다. |

Ridge는 고정된 분할과 파라미터에서 한 번 적합하면 된다. Kriging의 커널 파라미터를 수치 최적화하면 같은 데이터에서 여러 시작점으로 최적화가 안정적인지 확인할 수 있다. 신경망의 seed 반복은 학습 변동을 보여준다. 여러 seed가 같은 데이터를 보므로 새로운 물리 검증 케이스가 늘지는 않는다. 적응형 DOE에서 이전 학습 가중치부터 시작하는 warm start의 효과가 궁금하면 동일 데이터와 계산 예산에서 독립 재학습과 별도 비교한다. [학습 파이프라인의 변동 요인](https://proceedings.mlsys.org/paper_files/paper/2021/hash/0184b0cd3cfb185989f858a1d9f5c1eb-Abstract.html)

## 10개부터 어디까지 늘릴지

1. **사용할 설계 범위를 먼저 고정한다.** 적용할 형상·하중·재료 범위, 관심점 변위, 응력 평가 영역, 제약 허용값을 기록한다. 같은 형상·하중에서 얻은 노드, 시간 프레임, 리메시와 저·고충실도 쌍은 동일 그룹으로 묶는다. 학습 10개를 시험하려면 개발·최종 테스트용 독립 그룹의 예산을 추가로 남긴다. 전체 사용 가능 데이터가 10개뿐이면 간단한 물리식·Ridge·Kriging의 탐색 비교를 하고, 적용 판정에 부족한 독립 근거를 기록한다. [GroupKFold](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html)
2. **같은 평가셋으로 10 → 20 → 40 → 80개를 비교한다.** 초기 샘플링 시드와 설계 순서를 저장하고 고정 DOE에서는 작은 집합이 큰 집합에 포함되게 한다. 적응형 DOE도 방법별 초기 설계와 비용을 맞추고, 선택에 쓴 그룹과 독립 평가 그룹을 분리한다. 낮은 비용의 모형과 Ridge·Kriging을 먼저 비교하고, 장·시간 이력처럼 복잡한 출력을 써야 하거나 기준선이 요구 오차를 놓치는 경우 소형 신경망을 추가한다. 최종 테스트는 모델과 적용 규칙을 고른 뒤에 연다. [Nested CV와 선택 편향](https://doi.org/10.1186/1471-2105-7-91)
3. **예산을 쓰는 근거를 기록한다.** 시범 단계에서 검증 오차, 제약 오판, 계산 비용이 요구사항을 만족하면 표본 수를 더 늘릴 필요가 작다. 기준을 못 맞추고 새 샘플에서 개선이 보이면 다음 설계점 묶음을 해석한다. 오차가 정체돼 있으면 실패 그룹의 부족한 범위, 요소·메시 오차, 부적절한 입력 또는 모델 구조를 확인한 뒤 다음 실험을 고른다. 100개 해석에서 뽑은 100,000개 프레임과 독립 해석 100,000건은 따로 보고한다. 큰 데이터에서 정확 GP의 일반적인 밀집 학습 비용은 시간 $O(N^3)$, 저장 $O(N^2)$이므로 실제 규모에 맞는 저랭크·희소 GP나 다른 기준선을 검토한다. [GPML 8장](https://gaussianprocess.org/gpml/chapters/)

## 신경망은 어떤 점수에서 멈추나

무차원화한 변위·응력 오차를 학습할 때의 예다. $s_j$는 물리 허용오차 또는 학습 분할에서 정한 스케일이고, $w_j$는 응답별 중요도다. 이 값과 정규화 파라미터는 모델 선택 절차 안에서 정한다.

$$
\mathcal L(\theta)=\frac{1}{N}\sum_{i=1}^N\sum_j w_j\left(\frac{\hat y_{ij}(\theta)-y_{ij}}{s_j}\right)^2+\lambda\lVert\theta\rVert^2.
$$

예를 들어 `max_epochs=300`, `patience=20`에서 시작하고, 개발 검증 점수가 사전 설정한 `min_delta`만큼 개선될 때 최적 체크포인트를 저장한다. 마지막 epoch와 최적 epoch, 학습 시간, 끝난 이유를 기록한다. 이 숫자는 초기 설정이며 데이터와 모델 구조를 갖춘 시범 실행에서 조정한다. 최종 테스트의 결과를 보고 patience, epoch, seed를 다시 고르면 새 독립 평가가 필요하다. 배포용 단일 모델은 사전에 정한 적합 절차로 재학습하고 확인한다. 앙상블을 선택할 경우 정확도와 함께 실제 추론 비용을 벤치마크한다. [Early stopping 실증 연구](https://doi.org/10.1016/S0893-6080(98)00010-0)

## 우수성 판정과 설치 앱의 사용 기준

| 확인 대상 | 기록 단위와 판정 |
|---|---|
| 예측 오차 | 변위·응력의 단위가 있는 MAE와 최대 오차를 낸다. 같은 홀드아웃 그룹에서 후보와 기준선의 오차 차이를 구하고, 독립 그룹이 충분하면 두 모델에 같은 그룹을 복원추출해 불확실성을 나타낸다. 그룹 수가 적으면 각 그룹의 결과와 결론의 적용 범위를 보여준다. [그룹 단위 부트스트랩](https://doi.org/10.1111/j.1467-9868.2007.00593.x) |
| 학습 변동 | 같은 분할·비교 예산에서 seed별 점수와 범위를 제시한다. 평균, 산포, 최악을 함께 보고하며 최고 점수 하나를 근거로 모델을 고르지 않는다. |
| 제약 위반 위험 | 실제 제약을 위반했는데 예측이 통과시킨 건수와 통과 판정 건수를 함께 제시한다. 예를 들어 독립적이고 대표적인 통과 사례 10개에서 위반이 0건이어도, 이항모형의 단측 95% 위험 상한은 $1-0.05^{1/10}\approx25.9\%$다. 그룹 의존성과 배포 조건이 다르면 이 예제 계산을 그대로 적용할 수 없다. [NIST 정확 이항 신뢰한계](https://itl.nist.gov/div898/software/dataplot/refman2/auxillar/exacbino.htm) |
| 비용과 설계 결과 | 실패·재실행·최종 확인까지 포함한 동일 고충실도 호출 예산에서 가장 가벼운 실제 feasible 설계, 총 시간과 비용을 비교한다. 각 결과의 절대 기준과 의미 있는 개선량을 모델 비교 전에 정한다. |

예측 정확도를 개선하려는 경우 그룹별 주 지표의 차이를 기준선 오차에서 후보 오차를 뺀 값으로 정의한다. 사전 합의한 최소 개선량을 신뢰구간 하한이 넘고 제약 위반 위험과 추론 비용도 각각 허용 범위에 있을 때 우수성을 주장한다. 최적설계가 목표면 주 지표를 실제 제약을 만족한 질량의 개선으로 바꾼다. 신뢰구간이 충분히 좁아지지 않으면 추가 그룹이 필요한 상태로 남긴다.

앱이 대리모델을 호출할 때는 모델 버전, 입력 범위, 검증된 단위와 오차, 불확실성이 보정된 조건을 결과에 함께 표시한다. 적용 범위를 벗어난 입력, 제약 경계에 가까운 설계와 최종 채택 후보는 실제 솔버로 확인한다. 저장 기록에는 데이터·분할 해시, 그룹 ID 규칙, 고충실도 호출·실패 수, seed 목록, 학습 설정·체크포인트, 라이브러리·솔버 버전, 검증 결과를 남긴다. 이 실험에서 서로 다른 설계 데이터로 신경망을 학습하거나 10만 건의 필요성을 실측한 결과는 아직 없다.
